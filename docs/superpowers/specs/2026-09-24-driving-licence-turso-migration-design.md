# Driving Licence Platform — Supabase → Turso Migration Design

Date: 2026-09-24
Status: Approved (design review in chat on 2026-09-24)

## 1. Overview

The project is a Moroccan "Code de la Route" driver's license exam platform (Category B).
It was generated by Bolt as a Vite + React + TypeScript + Tailwind single-page app and uses
Supabase (Postgres + email/password auth) through the browser anon key + RLS.

This migration:

1. Flattens the Bolt project from `project/` into the repository root
   (`C:\Users\PC\Desktop\drivinglicence`).
2. Removes Bolt-specific artifacts and renames the package.
3. Replaces Supabase with Turso (SQLite-compatible), introducing a small Hono API server
   that owns the database credentials and handles admin authentication.
4. Fixes two pre-existing defects found while migrating (question reorder and N+1 queries).

## 3. Current architecture (before)

- React 18 + Vite 5 + TS + Tailwind 3 + react-router-dom 7 + lucide-react.
- `src/lib/supabase.ts` creates a Supabase client from `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`.
- `AuthContext` uses Supabase email/password auth; any authenticated user can write (RLS policy).
- Student side is public via the anon key.
- Tables: `series`, `questions` (UUID ids, RLS, integer[] `correct_answers`, timestamps).
- Question ordering is by `created_at`; the admin move-up/down action swaps `updated_at`,
  which has no effect on ordering (Bolt bug).
- Series list loads question counts with N+1 queries (Bolt inefficiency).

## 4. Target architecture (after)

- Frontend: unchanged stack, data access swapped to a typed fetch client.
- Backend: Hono Node server (`server/`) in the same repo. Holds Turso credentials, enforces
  auth, and is the only process that talks to the database. Deployable as a Node service
  (also compatible with Vercel/Railway later).
- Database: Turso (SQLite). In development, if `TURSO_DATABASE_URL` is absent, fall back to
  a local SQLite file `local.db` (gitignored) so the app runs without Turso credentials.
- Auth: email + bcrypt-hashed password in a `users` table. Server issues a JWT in an
  httpOnly cookie after login. First admin is bootstrapped from `ADMIN_EMAIL`/`ADMIN_PASSWORD`
  env vars on server start when the `users` table is empty. The signup ("Inscription") flow is
  removed: under Supabase it let any signed-up user write to the DB; in the new model open
  signup would grant admin. Login only.
- Dev workflow: `npm run dev` runs the Hono server + Vite together (`concurrently`); Vite
  proxies `/api` to `http://localhost:3001`.

## 6. Schema (SQLite)

### series
- `id` TEXT PRIMARY KEY (UUID generated in-app via `crypto.randomUUID()`)
- `title` TEXT NOT NULL
- `description` TEXT
- `is_active` INTEGER NOT NULL DEFAULT 1
- `category` TEXT NOT NULL DEFAULT 'B'
- `created_at` TEXT NOT NULL (ISO 8601)
- `updated_at` TEXT NOT NULL

### questions
- `id` TEXT PRIMARY KEY (UUID generated in-app)
- `series_id` TEXT NOT NULL REFERENCES series(id) ON DELETE CASCADE
- `image_url` TEXT
- `audio_url` TEXT
- `question_text` TEXT NOT NULL
- `question_text_2` TEXT
- `option_1` TEXT NOT NULL
- `option_2` TEXT NOT NULL
- `option_3` TEXT
- `option_4` TEXT
- `correct_answers` TEXT NOT NULL DEFAULT '[]' (JSON array of 1-based indices; parsed to
  `number[]` at the API boundary)
- `timer_duration` INTEGER NOT NULL DEFAULT 20 CHECK (timer_duration IN (10, 20, 30))
- `category` TEXT NOT NULL DEFAULT 'B'
- `position` INTEGER NOT NULL DEFAULT 0 (fills the reorder gap)
- `created_at` TEXT NOT NULL
- `updated_at` TEXT NOT NULL

### users
- `id` TEXT PRIMARY KEY (UUID generated in-app)
- `email` TEXT NOT NULL UNIQUE (stored lowercase)
- `password_hash` TEXT NOT NULL (bcrypt)
- `created_at` TEXT NOT NULL

No RLS — access is enforced in server code: student reads public; series/question writes and
reorder require a valid admin JWT.

Seed: insert "Series 1" if the table is empty (mirrors the Supabase seed).

## 7. API contract

All JSON. Write endpoints return 401 without a valid JWT cookie.

- `POST /api/auth/login` — {email, password} → 200 {user} + httpOnly JWT cookie, 401 on bad creds
- `POST /api/auth/logout` — clears cookie
- `GET  /api/auth/me` → {user} | 401 (used by AuthContext on load)
- `GET  /api/series` → active series + `question_count` (single JOIN query). `?all=true`
  (admin session) returns inactive too.
- `GET  /api/series/:id` → single series (public; used by exam screen and admin detail)
- `POST /api/series` — create (admin)
- `PUT  /api/series/:id` — update (admin)
- `DELETE /api/series/:id` — delete, cascades to questions (admin)
- `GET /api/series/:id/questions` — public, ordered by `position, created_at`
- `POST /api/questions` — create (admin)
- `PUT /api/questions/:id` — update (admin)
- `DELETE /api/questions/:id` — delete (admin)
- `PATCH /api/questions/reorder` — body {ids: string[]}; repositions in one transaction (admin)

Resource list endpoints return `[]`/null-normalized JSON so downstream TS types stay stable.

## 8. Frontend changes

- `src/lib/db.ts` replaces `src/lib/supabase.ts`: typed helper `api.get/post/put/patch/delete`
  returning `{ data }` or `{ error }`, browser cookies handled automatically by `fetch`
  (same-origin `/api`).
- `AuthContext`: `signIn` calls `POST /api/auth/login`; initial load calls `GET /api/auth/me`;
  `signUp` removed; context exposes `{ user, loading, signIn, signOut }`.
- `AdminLogin`: removes the "Inscription" tab (login only).
- Pages/modals swap `supabase.from('series'|'questions')…` chains for `api.*` calls.
  No UI/schema changes elsewhere.
- Verify TS could still derive `correct_answers: number[]` from JSON text — the API layer
  parses and re-stringifies transparently.

## 9. Configuration / environment

`.env.example`:

- `TURSO_DATABASE_URL` — optional in dev; required for Turso
- `TURSO_AUTH_TOKEN` — optional in dev
- `JWT_SECRET` — required in prod; dev default provided
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — bootstrap the first admin user on server start when the
  `users` table is empty (in `server/db.ts` after migrations run)

Vite no longer needs `VITE_*` Supabase vars; the old `.env` Supabase keys are removed.

## 12. Verification

No test framework exists. Verification = `typecheck` + `lint` + `build` + a live smoke test:

1. Start dev server; confirm student page lists "Series 1" with 0 questions.
2. Bootstrap admin; log in through the UI; create a series; add 3 questions.
3. Reorder questions; confirm exam screen order changed.
4. Take the exam; answer correctly/incorrectly; confirm result screen + score.
5. Confirm admin signup tab is gone and unauthenticated write attempts return 401.
